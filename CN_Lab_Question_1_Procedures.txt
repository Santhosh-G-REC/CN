SECTION A - CISCO PACKET TRACER
============================================================

GENERAL PACKET TRACER PROCEDURE
-------------------------------
1. Open Cisco Packet Tracer.
2. Place the required devices in the workspace.
3. Connect devices using the correct cable.
4. Configure IP address and subnet mask on every PC.
5. Configure router interfaces if a router is used.
6. Configure default gateway on PCs when communication crosses networks.
7. Change to Simulation mode if the question asks to observe packet movement.
8. Click Add Simple PDU (envelope icon), then click source PC and destination PC.
9. Check whether the packet is successful.
10. Use ping from PC -> Desktop -> Command Prompt to verify connectivity.

COMMON CABLES
-------------
PC to Hub: Copper Straight-Through
PC to Switch: Copper Straight-Through
Switch to Router Ethernet: Copper Straight-Through
Hub to Switch: Copper Cross-Over or Automatic
Router to Router Serial: Serial DCE/DTE cable
Laptop to Wireless Router: Wireless connection
Wireless Router to Cable Modem: Copper Straight-Through
Cable Modem to Cloud: Coaxial cable if supported by the selected devices

PC IP CONFIGURATION
-------------------
1. Click the PC.
2. Select Desktop.
3. Open IP Configuration.
4. Select Static.
5. Enter IP Address.
6. Enter Subnet Mask.
7. Enter Default Gateway if required.
8. Close the window.

To test:
Desktop -> Command Prompt
ping <destination-IP>

1. HUB WITH FOUR PCs
------------------------------------------------------------
AIM:
To build a LAN using one hub and four PCs and observe how the hub forwards a frame.

DEVICES: 1 Hub, 4 PCs (PC0 to PC3)

IP CONFIGURATION:
PC0: 192.168.1.1    Mask: 255.255.255.0
PC1: 192.168.1.2    Mask: 255.255.255.0
PC2: 192.168.1.3    Mask: 255.255.255.0
PC3: 192.168.1.4    Mask: 255.255.255.0

PROCEDURE:
1. Place one hub and four PCs.
2. Connect each PC to the hub using Copper Straight-Through cables.
3. Configure the IP addresses and subnet masks shown above.
4. Change to Simulation mode.
5. Select Add Simple PDU.
6. Click PC0 and then PC3.
7. Observe packet movement in the Simulation panel.
8. Record how the hub forwards the frame to its other ports.

EXPECTED OUTPUT / OBSERVATION:
The hub repeats the incoming signal to all other connected ports. All connected devices receive the signal, but only the destination PC processes the frame.

6. TWO SUBNETS - COMPARE WITH AND WITHOUT ROUTER
------------------------------------------------------------
AIM:
To compare packet transmission between two different subnets before and after connecting a router.

NETWORKS:
Subnet A: 172.16.1.0/24
Subnet B: 172.16.2.0/24
Each subnet has one switch and three PCs.

SAMPLE CONFIGURATION:
Subnet A:
PC0: 172.16.1.2 /24, Gateway 172.16.1.1
PC1: 172.16.1.3 /24, Gateway 172.16.1.1
PC2: 172.16.1.4 /24, Gateway 172.16.1.1

Subnet B:
PC3: 172.16.2.2 /24, Gateway 172.16.2.1
PC4: 172.16.2.3 /24, Gateway 172.16.2.1
PC5: 172.16.2.4 /24, Gateway 172.16.2.1

Router:
Interface for Subnet A: 172.16.1.1/24
Interface for Subnet B: 172.16.2.1/24

PROCEDURE:
1. Place two switches and six PCs.
2. Connect three PCs to each switch.
3. Configure the IP addresses for both subnets.
4. First, do not connect a router.
5. Send a Simple PDU from a PC in Subnet A to a PC in Subnet B.
6. Observe that communication between different subnets fails without a router.
7. Add a router and connect one interface to each switch.
8. Configure router interface IP addresses as shown above.
9. Enable both router interfaces using no shutdown.
10. Set each PC's default gateway to its router interface address.
11. Send the PDU again and observe successful packet transmission.

EXPECTED OUTPUT:
Without router: different subnets cannot communicate.
With router and correct gateways: communication succeeds.

7. FOUR SUBNETS FROM 192.168.10.0/24
------------------------------------------------------------
AIM:
To divide 192.168.10.0/24 into four equal subnets, connect them to a router and test connectivity.

SUBNETTING:
Original network: 192.168.10.0/24
Four equal subnets require /26.
Subnet mask: 255.255.255.192

FOUR SUBNETWORKS:
Subnet 1: 192.168.10.0/26
Usable hosts: 192.168.10.1 - 192.168.10.62
Broadcast: 192.168.10.63

Subnet 2: 192.168.10.64/26
Usable hosts: 192.168.10.65 - 192.168.10.126
Broadcast: 192.168.10.127

Subnet 3: 192.168.10.128/26
Usable hosts: 192.168.10.129 - 192.168.10.190
Broadcast: 192.168.10.191

Subnet 4: 192.168.10.192/26
Usable hosts: 192.168.10.193 - 192.168.10.254
Broadcast: 192.168.10.255

PROCEDURE:
1. Place one router, four switches and at least two PCs per subnet.
2. Connect each switch to a separate router interface. If the router has insufficient Ethernet interfaces, use a suitable supported module or topology allowed by your lab.
3. Assign two valid host IP addresses from each subnet to its PCs.
4. Assign one valid IP address from each subnet to the corresponding router interface.
5. Set the router interface subnet mask to 255.255.255.192.
6. Enable the interfaces using no shutdown.
7. Set each PC's default gateway to the router interface in its subnet.
8. Send Simple PDUs between devices in different subnets.
9. Verify using ping.

EXPECTED OUTPUT:
All four subnets should communicate through the router when interfaces, IP addresses and gateways are configured correctly.

8. SIMPLE INTERNETWORK USING ONE ROUTER AND TWO PCs
------------------------------------------------------------
AIM:
To connect two different networks using one router in Packet Tracer.

ROUTER CONFIGURATION:
FastEthernet0/0: 192.168.10.1/24
FastEthernet0/1: 192.168.20.1/24

PC CONFIGURATION:
PC0: 192.168.10.2/24, Gateway 192.168.10.1

11. STATIC ROUTING - TWO ROUTERS AND SERIAL LINK
------------------------------------------------------------
AIM:
To configure static routing between two LANs connected by two routers.

NETWORK DETAILS:
LAN1: 10.1.1.0/24
LAN2: 10.2.2.0/24
Serial link: 192.168.100.0/30

SAMPLE ADDRESSING:
R1 LAN interface: 10.1.1.1/24
PC0: 10.1.1.2/24, Gateway 10.1.1.1
R1 Serial: 192.168.100.1/30
R2 Serial: 192.168.100.2/30
R2 LAN interface: 10.2.2.1/24
PC1: 10.2.2.2/24, Gateway 10.2.2.1

PROCEDURE:
1. Place two routers and two PCs.
2. Connect each PC to its router LAN interface.
3. Connect the routers using a Serial DCE cable.
4. Configure IP addresses on PC and router interfaces.
5. On the DCE serial side, configure a clock rate if required:
   clock rate 64000
6. Enable all router interfaces using no shutdown.
7. Add a static route on R1 to reach LAN2:
   ip route 10.2.2.0 255.255.255.0 192.168.100.2
8. Add a static route on R2 to reach LAN1:
   ip route 10.1.1.0 255.255.255.0 192.168.100.1
9. Check routing tables:
   show ip route
10. Ping from PC0 to PC1.

EXPECTED OUTPUT:
The two PCs should communicate through the serial link using static routes.

12. STATIC ROUTING - THREE ROUTERS WITH MAIN AND BACKUP ROUTE

AIM:

13. RIP ROUTING - THREE ROUTERS IN A TRIANGLE
------------------------------------------------------------
AIM:

Three routers connected in a triangle using serial links from the 192.168.1.0/30 series.

PROCEDURE:

   network 20.0.0.0
   network 192.168.1.0
8. Repeat with the correct connected networks on each router.
9. Check the routing table:
   show ip route
10. Test connectivity between PC0 and PC1 using ping.

EXPECTED OUTPUT:
RIP routers exchange route information and learn remote networks. Ping should succeed when addressing and network statements are correct.

SECTION B - WIRESHARK
============================================================

GENERAL WIRESHARK PROCEDURE
---------------------------
1. Open Wireshark.
2. Select the active network interface (Wi-Fi or Ethernet).
3. Double-click the interface to start capturing.
4. Generate the required traffic (browse a website, ping, nslookup, renew DHCP, etc.).
5. Enter the required display filter in the filter bar.
6. Press Enter to apply the filter.
7. Select a packet and expand the required protocol fields.
8. If asked for a flow graph, choose Statistics -> Flow Graph.
9. Save the capture using File -> Save As.

COMMON DISPLAY FILTERS
----------------------
TCP:   tcp
UDP:   udp
ARP:   arp
DNS:   dns
HTTP:  http
ICMP:  icmp
DHCP:  dhcp (or bootp on some Wireshark versions)
IP:    ip

17. WIRESHARK - TCP PACKET CAPTURE
------------------------------------------------------------
AIM:
To capture TCP packets, inspect TCP header fields and display a flow graph.

PROCEDURE:
1. Open Wireshark and select the active LAN interface.
2. Start capturing packets.
3. Browse any website to generate TCP traffic.
4. Stop capture after collecting about 100 packets.
5. Enter display filter: tcp
6. Select a TCP packet.
7. Expand Transmission Control Protocol.
8. Note Source Port, Destination Port, Sequence Number, Acknowledgement Number and Flags.
9. Select Statistics -> Flow Graph.
10. Save the capture file.

EXPECTED OUTPUT:
TCP packets are displayed with source/destination ports, sequence and acknowledgement numbers, and flags.

18. WIRESHARK - ARP PACKETS
------------------------------------------------------------
AIM:
To capture and inspect ARP request and ARP reply packets.

PROCEDURE:
1. Open Wireshark and select the active interface.
2. Start capturing.
3. Open Command Prompt as administrator if needed.
4. Clear the ARP cache using the command supported by your OS. On Windows:
   arp -d *
5. Ping the default gateway: ping <gateway-IP>
6. Return to Wireshark and apply: arp
7. Select the ARP request and inspect Opcode, Sender MAC, Sender IP, Target MAC and Target IP.
8. Select the ARP reply and inspect the same fields.
9. Explain whether ARP has a transport-layer header.

EXPECTED OUTPUT / VIVA POINT:
ARP resolves an IPv4 address to a MAC address. It is not carried inside TCP or UDP, so it has no transport-layer header.

------------------------------------------------------------
19. WIRESHARK - DNS PACKETS
------------------------------------------------------------

To capture DNS query and response packets and inspect DNS traffic.

4. Return to Wireshark.

DNS query and response packets appear. DNS commonly uses UDP port 53; TCP port 53 is also used in some cases.

20. WIRESHARK - HTTP PACKETS

GENERAL NMAP PROCEDURE
----------------------
